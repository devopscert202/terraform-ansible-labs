AWS in nine ideas

This page assumes you have never opened the AWS console. Each section below defines one AWS concept in plain English and names the Terraform resource type that creates it, in the order the pieces stack up: a region holds a VPC, the VPC holds subnets, a subnet holds an instance, and a gateway plus a route table make that instance reachable. The diagram at the end is exactly what Lab 10 builds.

Read Terraform 101 first. This page teaches AWS, not Terraform. It shows HCL — the language Terraform configuration is written in — to name the resource type behind each AWS concept, and it assumes you have already met blocks, arguments and references there.

How to read the code blocks on this page

Enough to follow along, no more. Terraform 101 covers all of it properly.

You will seeWhat it means
resource "aws_vpc" "this" { Create and own one thing. aws_vpc is the resource type (which kind of AWS object); this is a name you choose to refer to it elsewhere in your own files.

Where things live

Region and Availability Zone

A region is a geographic cluster of AWS data centres, such as us-east-2 in North Virginia. Every resource you create belongs to exactly one region, and resources in different regions cannot see each other by default. An Availability Zone (AZ) is one isolated data-centre group inside a region, named by suffixing a letter: us-east-2a. This whole track uses us-east-2.

Example

provider "aws" {
  region = "us-east-2"
}

Line by line

LineWhat it does
provider "aws"Configures the AWS provider — the plugin that turns your configuration into AWS API calls. There is no Terraform resource for a region; the region is a provider setting.
regionEvery resource managed by this provider block is created here. Change it and Terraform will plan to recreate everything elsewhere.
Availability ZoneNot set here. It is an argument on zonal resources such as subnets, and this track never hardcodes one — it is resolved from data "aws_availability_zones". The subnet section below shows how.

Your network

VPC and CIDR

A VPC (Virtual Private Cloud) is your own private network inside a region. Nothing outside it can reach into it unless you explicitly open a path. Its size is fixed at creation by a CIDR block — a range of IP addresses written as address plus prefix length. 10.0.0.0/16 reserves 65,536 addresses from 10.0.0.0 to 10.0.255.255; the smaller the number after the slash, the larger the range.

Example

resource "aws_vpc" "this" {
  cidr_block           = "10.0.0.0/16"
  enable_dns_hostnames = true

  tags = { Name = "tflabs-capstone", Lab = "lab10" }
}

Line by line

LineWhat it does
aws_vpcThe Terraform resource type for a VPC.
cidr_blockThe address range. It cannot be shrunk later, so pick a /16 and carve subnets out of it.
enable_dns_hostnamesGives instances with a public IP a resolvable public DNS name.
tagsFree-form key/value labels. Every resource in this track carries Name and Lab.
Check you have a default VPC before your first apply. An aws_instance with no subnet_id, or an aws_security_group with no vpc_id, is placed in the region's default VPC — a VPC AWS pre-creates per region. A fresh training account may have none, and terraform plan does not detect it: the failure appears only at apply, as VPCIdNotSpecified: No default VPC for this user. Labs 15 and 21 rely on it; every other AWS lab builds its own network. Check, then create one if the result is empty:
aws ec2 describe-vpcs --filters Name=isDefault,Values=true \
    --query 'Vpcs[].VpcId' --output text

aws ec2 create-default-vpc
Lab 10 is unaffected because it builds its own VPC and sets subnet_id and vpc_id explicitly. That is the better pattern: the network a resource lands in is stated in the configuration rather than inherited from whatever the account happens to have.

Slicing the network

Subnet — public versus private

A subnet is a slice of the VPC's address range, pinned to one Availability Zone. The words public and private are not AWS settings: a subnet is public when its route table sends internet-bound traffic to an internet gateway, and private when it does not. map_public_ip_on_launch additionally hands every instance launched there a public IP address.

Example

data "aws_availability_zones" "available" {
  state = "available"
}

resource "aws_subnet" "public" {
  vpc_id                  = aws_vpc.this.id
  cidr_block              = "10.0.1.0/24"
  availability_zone       = data.aws_availability_zones.available.names[0]
  map_public_ip_on_launch = true
}

Line by line

LineWhat it does
aws_subnetThe Terraform resource type for a subnet.
vpc_idPlaces the subnet inside the VPC. This reference is also what tells Terraform to create the VPC first.
cidr_blockA /24 (256 addresses) carved out of the VPC's /16. Subnet ranges may not overlap.
data "aws_availability_zones"Asks the account which zones it can actually use. Zone names are mapped per account, so us-east-2a is not the same hardware in two accounts and may be absent or out of capacity in yours.
availability_zonePins the subnet to one AZ, which must sit inside the provider's region. Take it from the data source with names[0] rather than hardcoding a name — this is what Lab 10 does, and it is not a value you set by hand.
map_public_ip_on_launchAuto-assigns a public IPv4 address to instances launched in this subnet.

The way out

Internet Gateway

An internet gateway is the door between your VPC and the public internet. It is a single, horizontally scaled component you attach to one VPC — you do not size it, patch it, or pay for it. Creating one changes nothing on its own: traffic only uses it once a route table points at it.

Example

resource "aws_internet_gateway" "this" {
  vpc_id = aws_vpc.this.id

  tags = { Name = "tflabs-capstone-igw", Lab = "lab10" }
}

Line by line

LineWhat it does
aws_internet_gatewayThe Terraform resource type. One per VPC is the normal case.
vpc_idAttaches the gateway to the VPC. An unattached gateway carries no traffic.

Traffic direction

Route table

A route table is a list of rules that answer one question: for a given destination address, where do I send the packet? Each rule pairs a destination CIDR with a target. Every VPC has a default local route so subnets can talk to each other; you add 0.0.0.0/0 pointing at the internet gateway to reach everything else. A table only affects a subnet once it is associated with it.

Example

resource "aws_route_table" "public" {
  vpc_id = aws_vpc.this.id

  route {
    cidr_block = "0.0.0.0/0"
    gateway_id = aws_internet_gateway.this.id
  }
}

resource "aws_route_table_association" "public" {
  subnet_id      = aws_subnet.public.id
  route_table_id = aws_route_table.public.id
}

Line by line

LineWhat it does
aws_route_tableThe Terraform resource type for the table itself.
routeOne rule. 0.0.0.0/0 means every address not matched by a more specific route — the default route.
gateway_idSends that traffic to the internet gateway.
aws_route_table_associationBinds the table to a subnet. Without it the subnet keeps the VPC's main table and stays private.

Instance firewall

Security group

A security group is a stateful firewall attached to an instance's network interface. Ingress rules allow traffic in, egress rules allow it out, and everything not explicitly allowed is denied. Stateful means a reply to an allowed inbound request is automatically allowed back out, so you rarely need matching rule pairs.

Example

resource "aws_security_group" "web" {
  description = "Allow inbound web traffic, all outbound"
  vpc_id      = aws_vpc.this.id

  ingress {
    description = "Inbound HTTP"
    from_port   = var.http_port  # 80
    to_port     = var.http_port
    protocol    = "tcp"
    cidr_blocks = [var.allowed_cidr]
  }

  egress {
    from_port   = 0
    to_port     = 0
    protocol    = "-1"
    cidr_blocks = ["0.0.0.0/0"]
  }
}

Line by line

LineWhat it does
aws_security_groupThe Terraform resource type.
vpc_idPlaces the group in your VPC. Omit it and the group is created in the region's default VPC instead — see the warning in the VPC section above.
dynamic "ingress"Generates one ingress rule per element of the list instead of repeating the block by hand. Lab 10 opens a single port, 80.
from_port / to_portA port range. Setting both to the same number opens exactly one port.
cidr_blocksWho may connect. Lab 10's allowed_cidr defaults to 0.0.0.0/0, the entire internet — defensible for a public web port, dangerous for an administrative port such as SSH on 22. Narrow it to your own address outside a lab account.
egressOutbound, written as one ordinary block. Groups are stateful, so replies to allowed inbound requests need no rule of their own.

Compute

EC2 instance

An EC2 instance is a virtual machine. You choose an instance type for its CPU and memory (t3.micro here) and an AMI — a machine image that supplies the operating system. Resolve the AMI with a data source rather than pasting an ID, because IDs differ per region and change whenever AWS republishes the image. user_data is a script run once on first boot.

Example

data "aws_ami" "al2023" {
  most_recent = true
  owners      = ["amazon"]

  filter {
    name   = "name"
    values = ["al2023-ami-2023.*-x86_64"]
  }
}

resource "aws_instance" "web" {
  ami           = data.aws_ami.al2023.id
  instance_type = "t3.micro"
  subnet_id     = aws_subnet.public.id
}

Line by line

LineWhat it does
data "aws_ami"Reads an existing image rather than creating one. Data sources look things up; resources create things.
most_recentOf the images matching the filters, take the newest. Combined with the name filter this always yields current Amazon Linux 2023.
aws_instanceThe Terraform resource type for a virtual machine.
subnet_idPlaces the instance in the public subnet, which is what earns it a public IP.

Instance login

Key pair

A key pair is an SSH public/private key used to log into a Linux instance. AWS stores the public half and attaches it to the instance at launch; the private half stays on your machine and is never uploaded. No lab in this track creates a key pair: the capstone is verified over HTTP, and Lab 15 connects over SSH to a host you supply, reading an existing private key from disk.

Example

resource "aws_key_pair" "lab" {
  key_name   = "tflabs-key"
  public_key = file("~/.ssh/id_rsa.pub")
}

resource "aws_instance" "web" {
  key_name = aws_key_pair.lab.key_name
  # ...
}

Line by line

LineWhat it does
aws_key_pairThe Terraform resource type.
public_keyOnly the public half. Never place a private key in a .tf file or in git.
key_nameOn the instance, names the key injected at launch. It cannot be changed without replacing the instance.
using an existing keyLab 15 skips aws_key_pair entirely and reads a private key you already have with private_key = file(pathexpand(var.private_key_path)), marked sensitive = true.

Authentication

IAM access keys

Terraform calls the AWS API as some identity, and in a lab account that identity is an IAM user holding an access key. The pair is an access key ID (begins AKIA, not secret) and a secret access key (shown exactly once, fully secret). Supply them as environment variables, never as arguments in a .tf file, and rotate them when the lab ends.

Example

unset AWS_PROFILE AWS_SESSION_TOKEN
export AWS_ACCESS_KEY_ID="AKIA..."
export AWS_SECRET_ACCESS_KEY="..."
export AWS_DEFAULT_REGION="us-east-2"

aws sts get-caller-identity

Line by line

LineWhat it does
unset AWS_PROFILEA leftover profile overrides these variables. Set to an empty string it fails with The config profile () could not be found.
AWS_ACCESS_KEY_IDIdentifies the IAM user. The AWS provider reads it automatically — no credentials argument is required.
AWS_SECRET_ACCESS_KEYThe secret half. Treat it like a password: no .tf file, no git, no screenshot.
aws sts get-caller-identityConfirms which account and identity Terraform will act as. Run it before every apply.

Putting it together

The Lab 10 architecture

Seven resources, one reachable web server. Follow the numbered blue arrows: 1 a request from the internet reaches the internet gateway; 2 the gateway passes it into the public subnet; 3 it arrives at the security group guarding the instance; 4 the ingress rule for TCP 80 admits it to the EC2 instance, where httpd serves the page the user-data script wrote at first boot; 5 the reply returns the same way. The security group is stateful, so the response needs no matching egress rule.

The route table is drawn with dashed grey lines because it carries no packets. It is what makes step 2 possible: its 0.0.0.0/0 route targets the internet gateway, and aws_route_table_association binds the table to the public subnet. Without the association the subnet falls back to the VPC's main table, which has no default route, and step 2 fails. Remove any one piece and the path breaks.
